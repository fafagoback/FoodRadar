# FoodRadar 歷史價格與促銷計算規則

## 唯一比較基準：上次有效實質單價 → 本次有效實質單價

- 比較同一個店家 UUID 與商品 UUID，不限制相隔日數、七日窗口或快照批次數。
- 每一次有效採集都算一次比較；180→120 是降價，下一次 120→120 就是持平，不因為變價事件仍顯示 180→120 而再次顯示降價。
- **唯一判斷入口**：`src/price_change.py:PriceChange.compare`，各 Python 流程透過 `PriceChange.qualifies` 與 `PriceChange.persisted` 使用同一結果。
- `serving_state.products` 永久保存 `reference_price`、`price_direction`、`is_price_drop`、`price_change_amount`、`price_change_percent`、`discount_amount`、`discount_pct`、`is_price_deal`。**是否降價由 Python 一次決定**；Turso、JavaScript 只能讀取 `is_price_drop`，不得從方向或百分比再判斷一次。
- 前端不再有價格漲跌計算函式；`web/packed-turso.js` 直接映射既有欄位，`web/app.js` 僅顯示與篩選。
- 只要本次價格比前次低，就是降價。30% 或省下多少元只是篩選條件，不是降價定義；不根據商家的促銷標籤判斷。
- 商品詳情標頭查詢目前商品列的前次有效單價；有效採集須保存精簡的 PRICE_OBSERVED 或變價事件；圖表以每日有效價格資料作點，不能把變價事件誤認為全部採集。

## 實質單價計算規則

所有歷史漲跌、歷史降價幅度、降價 30% 篩選、促銷交叉分類及價格走勢，皆以相同規格的**實質單件成本**計算，不得將上次的商品標價與這次的實質單價直接比較。

- 一般單件：實質單價 = 菜單可支付標價。
- 無促銷多入組：實質單價 = 組合可支付價格 ÷ 件數。
- 買 B 送 F：實質單價 = (菜單每件可支付價格 × B) ÷ (B + F)。
- 第 2 件半價：實質單價 = 菜單單價 × 1.5 ÷ 2。
- 加 1 元多 1 件：實質單價 = (菜單單價 + 1) ÷ 2。
- 平台直接標註 N 折：菜單售價已是折後支付金額，不可再次套用折數。
- 抽取不到有效價格、店家未營業時的不可下單標價：不可用作比較基準。

歷史參考價 `reference_price` 為上一筆經驗證的**實質單價**，而 `products.price` 及 `recent_prices` 仍保留付款標價。資料庫 `effective_price` 與前端單價必須一致。

```text
價格變化百分比 = (本次實質單價 - 上次實質單價) / 上次實質單價 × 100%
降價百分比 = max(0, -價格變化百分比)
每件省下金額 = max(0, 上次實質單價 - 本次實質單價)
```

僅有已驗證、同品項的前後實質單價有效且本次較便宜時才顯示「實質降價」。降價 30%+ 篩選須與首頁同源。平台促銷標籤屬另一種判斷，兩者可以同時成立，也可以分開成立。

## 具體案例

2026/10/13：鬆餅家「鮮檸冬瓜露」標價 89 元，買 1 送 1，實質單價 44.50 元。

2026/10/21：標價 55 元，無促銷，實質單價 55 元。

結果：單價上漲 10.50 元、漲幅約 23.6%。不是 89 → 55 降價 38.2%，也不是「歷史實質降價」。

## 圖表與畫面顯示

- 歷史圖表的 Y 值必須為**未提前取整**的有效實質單價；歷史表格和卡片採用相同單價定義。
- 金額呈現可遵循 Uber Eats 台灣介面顯示整數元，計算時必須保留至少小數點後 2 位，避免誤差。
- `PRICE_CHANGED` 和 `PROMOTION_CHANGED` 都可能代表實質單價變動。相同採集時間只畫一個點。
- 原始標價與促銷狀態仍需保留，使用者可以理解單價變化原因。
- 修改計算定義後，應從歷史快照重建服務資料庫和查詢索引，不可沿用舊標價導出的 `discount_pct`。


## 最新有效批次才可上架
- 商品搜尋、一般商品、平台促銷及降價清單都必須核對 `product.last_seen == store.last_seen == metadata.latest_processed_at`。
- 最新批次沒有取得可使用的有效單價，商品就不得出現在目前清單，即使前次的促銷或降價尚儲存在歷史表中。
- 刪除 36 小時寬限期，使用最新批次觀測而非距離現在的時間來判定。
- 只有本次與前次有效實質單價經 Python `PriceChange` 判定下降，才標示降價；持平為 0%。
- 過去價格仍留存以供趨勢及下一次有效採集比較，不可用舊資料假裝今天有效。


## 歷史誤判修復（2026-10-27）
- 抓取的原始 JSON 曾出現 `isOpen=true` 同時 `closedMessage="Delivery unavailable"`，舊版誤將其當成有效價格；重新播放 HF 原始批次時必須完整排除。
- 同 UUID 商品可能同時出現在 `Featured items`、`Buy 1, get 1 free` 及一般分類，須收集所有分類的優惠證據，而非以首次出現為準。
- 舊 `PRICE_CHANGED` 與 `PROMOTION_CHANGED` 事件可能來自不可外送時段；只更新前台篩選不足以修好走勢，必須用新版驗證器對原始快照整庫重建。


## 七日低價主清單規則（2026-10-27）
- 最新有效實質單價相較於本次之前 7 天內最高有效實質單價，降幅達 30% 才列入主清單。
- 從驗證通過的 NEW、PRICE_OBSERVED、PRICE_CHANGED、PROMOTION_CHANGED 事件中計算，每一時間點只取一筆實質單價。
- 歷史原價即使僅出現一次，只要有效也可作為七日基準；時間超過七天自然剔除。
- reference_price、price_direction 繼續表示「前次 vs 本次」；seven_day_* 表示七日主清單，前端不能自行重新計算。
- 最新批次沒抓到有效單價的商品絕不進入搜尋索引。
